# 屏幕适配说明（800×480 车载横屏 + 手机）

> 本文档对应 v2.1 起的**统一顶栏布局**。早期版本曾按可用宽高在「侧栏 / 顶部标签 / 底部导航」
> 三套外壳间切换，并在色彩页放了一个圆形色盘；真机（800×480 车机）实测后已删除——见文末「为什么不这么做了」。
>
> 桌面卡片（App Widget）的尺寸与交互是另一套体系，见 [`widgets.md`](widgets.md)。

## 1. 结构

所有屏幕共用一套外壳：

```
┌──────────────────────────────────────────────┐
│  色彩  │  模式  │  设备  │  关于              │  58 dp 顶栏
├──────────────────────────────────────────────┤
│  ● 已连接 3F:2A:9C:11:04:8E           断开    │  40 dp 状态行
├──────────────────────────────────────────────┤
│                                              │
│        [ 32 色预设网格，居中 ]                │  剩余高度
│                                              │
├──────────────────────────────────────────────┤
│  分区1 │ 分区2 │ 全区 │ 开启 │ 关闭 │ 跟随    │  116 dp 控制条
│  亮度 ───────────────●──────────            │
└──────────────────────────────────────────────┘
```

固定开销 98 dp（顶栏 + 状态行），控制条 116 dp（窄屏 168 dp），其余全给网格。

## 2. 为什么菜单在顶部

800×480 的屏，**横向富余、纵向稀缺**：

| 方案 | 竖向占用 |
|---|---|
| 底部导航 + 状态行 | 60 + 40 = 100 dp |
| 左侧栏 + 状态行 | 88 dp 宽 + 40 dp 高 |
| **顶部标签 + 状态行** | **58 + 40 = 98 dp** |

三种方案的竖向开销接近，但顶部菜单把「导航」和「内容」放在同一条视觉动线上，
且不和车机自带的底部系统栏抢位置。配合「去掉色盘、改预设网格」，纵向空间全部让给了 32 个色块。

## 3. 唯一随屏幕变化的量：网格列数

```kotlin
val columns = if (wide) 8 else 4     // wide = maxWidth >= 640.dp
```

色块直径不是写死的，而是按可用空间算出来：

```kotlin
val cellWidth  = (maxWidth  - pad * 2 - gap * (columns - 1)) / columns
val cellHeight = (gridHeight - pad  - gap * (rows - 1))     / rows
val diameter   = minOf(cellWidth, cellHeight).coerceIn(30.dp, 118.dp)
```

这样同一个 APK 在任何屏上都自动取到「塞得下的最大圆」，不会出现色块溢出或被压扁。

| 实机 | 物理 | density | 折算 dp | 列数 | 色块直径 | 控制条 |
|---|---|---|---|---|---|---|
| 车机（实测） | 800×480 | mdpi 160 | 800×480 | 8 × 4 | ≈56 dp | 单行 |
| 车机 | 800×480 | hdpi 240 | 533×320 | 8 | 触底 30 dp，网格可滚动 | 单行 |
| 车机 | 800×480 | tvdpi 213 | 601×361 | 8 | ≈40 dp | 单行 |
| 手机竖屏 | 1080×2400 | xxhdpi 480 | 360×800 | 4 × 8 | ≈58 dp | 分两行 |
| 手机横屏 | 2400×1080 | xxhdpi 480 | 800×360 | 8 × 4 | ≈52 dp | 单行 |

窄屏（< 480 dp）时控制条自动拆成「分区 / 开关 / 亮度」三行，避免 6 个 chip 挤成一团。

## 4. 车载专项

| 问题 | 处理 |
|---|---|
| 手指粗、车在动 | 色块取「可用空间能容纳的最大圆」；按钮最小 48 dp；文字整体上调一档（正文 16 sp） |
| 拖拽精度差 | **移除圆形色盘**，改为 32 个预设色块，一次点击即命中 |
| 需要一眼看清状态 | 状态行常驻：色点 + 文字 + 断开/重连 |
| 开车不能熄屏 | 连接成功后 `keepScreenOn = true`，断开自动取消 |
| 车机常横屏 | 不锁 `screenOrientation`，交给面板决定 |
| 旋转/换屏打断连接 | `configChanges` 含 `orientation|screenSize|density`，Activity 不重建 |
| 廉价 TN 面板对比度低 | 全深色 + 高对比强调色；选中色块用「白/黑自适应」描边 + 中心点，深浅底色都看得见 |

## 5. 为什么不这么做了（v2.0 → v2.1 的取舍）

v2.0 实现了三套外壳 + 圆形色盘，真机 800×480 实测后的结论：

1. **三套外壳是过度设计**。真机车机固定横屏、固定分辨率，实际只命中其中一套；
   多出来的侧栏/底栏代码是纯负担。
2. **色盘不适合车机**。环形渐变靠角度命中，选中某一色需要精确拖拽，
   开车时基本不可用；32 个预设块反而更快更准。
3. **侧栏浪费横向空间**。800 dp 宽被侧栏吃掉 88 dp，而这 88 dp 给色块正好。

因此 v2.1 收敛为一套顶栏布局 + 预设网格，代码量减少约 25%（删掉 `HueWheel`、
`LayoutMode`、`NavigationRail`/`BottomBar` 分支），同时色块尺寸和字号都变大了。

## 6. 如何自测

1. Android Studio → Device Manager → New Hardware Profile：800×480、density 240（最容易出问题的一档）
2. 真机/模拟器上确认：
   - 顶栏 4 个 tab 都在一屏内、无换行
   - 32 个色块完整可见（或可滚动），直径 ≥ 48 dp
   - 控制条的 6 个 chip 文字不被截断
3. 用 Android 12+ 的自由窗口把窗口拖到 400×300，确认网格自动降到 4 列且可滚动、不重叠。
